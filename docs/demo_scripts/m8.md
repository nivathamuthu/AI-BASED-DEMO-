# Module 8 demo script (90 seconds)

Before recording: `.\make.ps1 up`, the corpus ingested, `.\make.ps1 extract-rules`, and a real provider in `.env` (the page shows a yellow banner when it is the mock). Open http://localhost:8010/agents/.

1. (0:00-0:10) Point at the provider line: Gemini model, local embeddings, retrieval mode, max loops 2, Postgres checkpointer. "Every step is a LangGraph node with a Pydantic-validated output."
2. (0:10-0:35) Click the first example, "Part 65-45210-3 is at 11,800 flight hours on a narrow-body aircraft. Is it due for replacement now?", then Ask. The trace fills in live: classify (compliance_check), plan (the tools it chose), hybrid_retrieve, graph_lookup, rule_check, draft, verify_citations. Open one row's tool call to show the arguments and the retrieved citations, and one LLM call with attempts and latency.
3. (0:35-0:55) The page reloads at the pause: "Pending approval". Read the red box: R-0020 from EO-2291 says 11500, R-0015 and R-0005 say 12000. "The agent does not pick a side. It says the documents conflict and cites both." Show the citation check line: every quote was found in its source and the judge accepted it.
4. (0:55-1:10) A verification loop, if one happened in this run or an earlier one: open a run whose trace shows verify_citations at loop 0 followed by hybrid_retrieve at loop 1. Open the verify row: the judge's reason (for example, a 50-hour maintenance deferral described as an MEL deferral) and the refined query. If no run looped, say so, and show the cap from the tests instead: `pytest apps/agents -k cap`.
5. (1:10-1:25) Back on the paused run: type "Follow EO-2291 until engineering resolves the conflict" and click Approve. The graph resumes from the checkpoint on the worker. The final answer shows the citation table: claim, verbatim quote, document, page, section, verified.
6. (1:25-1:30) Terminal: `.\make.ps1 eval-agent`. Read the table header (provider/model) and one honest line about whatever failed.
