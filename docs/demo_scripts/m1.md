# Module 1 demo script (about 2 minutes)

Open http://localhost:8010/ingest/ with the worker log visible (`.\make.ps1 worker` in another terminal).

1. Point at the three synthetic files and say what each format is for: the PDF carries the exact strings `AD 2023-14-09` and `PN-77-4418`, the DOCX is the maintenance planning procedure, the PPTX is the briefing.
2. If the table is already filled by `.\make.ps1 demo`, open the PDF row. Otherwise upload `data/corpus/synthetic/airworthiness_directive_excerpt.pdf` and wait for the badge to turn Done. The row polls by itself.
3. On the document page, point at the stage table. Seven stages, each with a time in milliseconds and a one-line summary (pages, chunks, the identifier list). That is the pipeline, not a single "embed this" call.
4. Point at a chunk. It has a page, a section path such as `2. Required action`, and the tags `ad AD 2023-14-09` and `part PN-77-4418`. Say that those three fields are what a citation needs later.
5. Upload the same PDF again. The message says it was already ingested, and no second row appears. The hash under the title is the reason.
6. Optional, if you want the retry on camera: set `INGEST_CHAOS_STAGE=parse` in `.env`, run `docker compose up -d web worker`, click Reprocess, and show Attempts = 2 on the parse row with the run still ending Done.

Close with the chunk count and the total milliseconds. Numbers, not a description of the architecture.
