# Module 4 demo script (about 3 minutes)

Load the corpus first (`.\make.ps1 demo`). Each finished upload hands its chunks to the graph task, so the graph is already there. Open http://localhost:8010/kg/.

1. Read the counts: nodes, edges, merged duplicates, dropped relations. Say where they come from: one validated extraction per chunk, cached in `KGExtraction`, so a rebuild costs no LLM calls.
2. Tick Part and Regulation, then Filter. Point at `AD 2023-14-09 -APPLIES_TO-> 65-45210-3` and `PN-77-4418 -REPLACES-> 65-45210-3`.
3. Click `PN-77-4418`. The panel lists the alias `P/N 77-4418` (the briefing deck spells it that way), every relation, and the source chunks with document, page and section.
4. Ask `Which tasks are governed by AD 2023-14-09 for part 65-45210-3?`. GraphRAG names both tasks. The hybrid-only answer beside it is one sentence. Scroll to Traversed path: the matched entities, each fact with its hop, the facts the answer used, and a citation per fact.
5. Show the naive prompt: `docker compose exec web python manage.py build_graph --extract --force --prompt-version v1`. The dropped-relations count goes up, because v1 names endpoints that are not in its own entity list. Rebuild with `--prompt-version v2` afterwards.
6. Run `docker compose exec web python manage.py eval_kg`. The table compares hybrid and GraphRAG per question, names the LLM, the embeddings and the graph build, and prints one winning case and one tie. With the mock LLM the numbers show what context each method hands the model; rerun with a real provider for a model-graded result.
